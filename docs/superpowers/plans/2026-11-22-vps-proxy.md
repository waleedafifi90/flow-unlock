# VPS Proxy Integration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Route Google/Flow traffic through the user's authenticated US VPS proxy, toggled from the extension, so Flow's `/unavailable` region block is bypassed.

**Architecture:** A `3proxy` HTTP proxy on the Ubuntu VPS. A shared pure module (`proxy-core.js`) decides which hosts to proxy and builds the Chrome PAC. `background.js` feature-detects the browser (`chrome.proxy.settings` = Chrome, `chrome.proxy.onRequest` = Firefox) and applies or clears the proxy, answering the proxy auth challenge from stored credentials. The popup gains a second toggle and the proxy fields. `engine.js` is untouched.

**Tech Stack:** MV3 extension (Chrome + Firefox), vanilla JS, `chrome.proxy` / `browser.proxy.onRequest`, `webRequest.onAuthRequired`, Node's built-in test runner for the pure module, 3proxy + systemd + UFW on Ubuntu.

**Spec:** docs/superpowers/specs/2026-11-22-vps-proxy-design.md

## Global Constraints

- Chrome build manifest adds permissions `proxy`, `webRequest`, `webRequestAuthProvider`.
- Firefox build manifest adds permissions `proxy`, `webRequest`; Firefox 128+ only (already pinned).
- Both manifests expand `host_permissions` to the proxied Google set (so `onAuthRequired` can read those requests).
- Only `firefox/manifest.json` and the two manifests' background wiring differ; all other files are byte-identical and mirrored by `build-firefox.sh`.
- Proxy credentials are supplied only when `details.isProxy` is true — never to a site's own login.
- Proxy password/host/port/user are user-entered at runtime; never hard-coded or committed.
- Commit attribution footer: `Co-Authored-By: Claude Opus 4.8 <noreply@anthropic.com>`.

## Review Focus

- **Incomplete config** (blank password/host) must not apply a proxy or break browsing → tested in Task 1 (`isCompleteProxyConfig`).
- **Toggle off** must fully restore DIRECT with no leftover PAC/listener → tested in Task 1 (`proxyDecision` returns `clear`) + manual in Task 2.
- **Non-Google hosts** must stay DIRECT (no accidental full-traffic proxy) → tested in Task 1 (`matchesProxyHost('example.com')` false).
- **Sign-in hosts** (accounts.google.com, apis) must be proxied too, or login/Flow IP mismatch trips "unusual activity" → tested in Task 1 (those hosts match).
- **Auth scope**: credentials returned only for `isProxy` requests → manual verification in Task 2 (site login still prompts normally).

### Task 1: Proxy core (pure, unit-tested)

**Files:**
- Create: `proxy-core.js`
- Test: `test/proxy-core.test.js`

**Interfaces:**
- Produces:
  - `GOOGLE_HOST_PATTERNS: string[]` — suffix patterns, e.g. `"flow.google.com"`, `"labs.google"`, `"accounts.google.com"`, `"googleapis.com"`, `"gstatic.com"`, `"apis.google.com"`, `"play.google.com"`, `"googleusercontent.com"`.
  - `matchesProxyHost(hostname: string, patterns = GOOGLE_HOST_PATTERNS) -> boolean` — true when hostname equals a pattern or ends with `"." + pattern`.
  - `isCompleteProxyConfig(config) -> boolean` — true when `host` (non-empty string), `port` (integer 1–65535), `username` and `password` (non-empty strings) are all present.
  - `proxyDecision(enabled: boolean, config) -> "apply" | "clear"` — `"apply"` only when `enabled` and `isCompleteProxyConfig(config)`, else `"clear"`.
  - `buildPac(host: string, port: number, patterns = GOOGLE_HOST_PATTERNS) -> string` — a PAC `FindProxyForURL` returning `"PROXY host:port"` for matching hosts, `"DIRECT"` otherwise.
- Ends with `if (typeof module !== "undefined") module.exports = { ... }` (same Node guard as engine.js).

- [ ] **Step 1: Write the failing test** `test/proxy-core.test.js` (CommonJS, `node:test` + `node:assert`):

```js
const { test } = require("node:test");
const assert = require("node:assert");
const C = require("../proxy-core.js");

test("matches google + subdomains, not others", () => {
  assert.ok(C.matchesProxyHost("flow.google.com"));
  assert.ok(C.matchesProxyHost("accounts.google.com"));
  assert.ok(C.matchesProxyHost("content.googleapis.com"));
  assert.ok(!C.matchesProxyHost("example.com"));
  assert.ok(!C.matchesProxyHost("notgoogle.com"));
});

test("config completeness", () => {
  assert.ok(C.isCompleteProxyConfig({ host: "1.2.3.4", port: 8443, username: "u", password: "p" }));
  assert.ok(!C.isCompleteProxyConfig({ host: "1.2.3.4", port: 8443, username: "u", password: "" }));
  assert.ok(!C.isCompleteProxyConfig({ host: "", port: 8443, username: "u", password: "p" }));
  assert.ok(!C.isCompleteProxyConfig({ host: "1.2.3.4", port: 0, username: "u", password: "p" }));
});

test("decision", () => {
  const good = { host: "1.2.3.4", port: 8443, username: "u", password: "p" };
  assert.equal(C.proxyDecision(true, good), "apply");
  assert.equal(C.proxyDecision(false, good), "clear");
  assert.equal(C.proxyDecision(true, { host: "" }), "clear");
});

test("pac proxies google, direct otherwise", () => {
  const pac = C.buildPac("1.2.3.4", 8443);
  const run = new Function(pac + "\nreturn FindProxyForURL;")();
  assert.equal(run("https://flow.google.com/x", "flow.google.com"), "PROXY 1.2.3.4:8443");
  assert.equal(run("https://example.com/", "example.com"), "DIRECT");
});
```

- [ ] **Step 2: Run to verify it fails** — `node --test test/` → FAIL (cannot find module `proxy-core.js`).
- [ ] **Step 3: Implement `proxy-core.js`** with the Interfaces above. `buildPac` emits a `FindProxyForURL(url, host)` that lowercases `host` and checks each pattern with the same suffix rule as `matchesProxyHost`.
- [ ] **Step 4: Run to verify it passes** — `node --test test/` → PASS.
- [ ] **Step 5: Commit** — `git add proxy-core.js test/proxy-core.test.js && git commit`.

### Task 2: Background proxy apply/clear + auth

**Files:**
- Modify: `background.js`

**Interfaces:**
- Consumes Task 1: `matchesProxyHost`, `proxyDecision`, `buildPac`, `GOOGLE_HOST_PATTERNS`.
- Storage keys added: `proxyEnabled` (boolean), `proxyConfig` (`{host, port, username, password}`).

- [ ] **Step 1: Load the core.** At the top of `background.js`, when `importScripts` exists (Chrome SW), call `importScripts("proxy-core.js")`; Firefox loads it via its manifest scripts array (Task 4), so guard the call. The pure names are then global.
- [ ] **Step 2: Implement `applyProxyState()`** in `background.js`: read `proxyEnabled`/`proxyConfig`; branch on `proxyDecision(...)`.
  - `apply` + `chrome.proxy.settings` (Chrome): `chrome.proxy.settings.set({ value: { mode: "pac_script", pacScript: { data: buildPac(config.host, config.port) } }, scope: "regular" })`.
  - `apply` + `chrome.proxy.onRequest` (Firefox): add a `proxy.onRequest` listener (filter `urls: ["<all_urls>"]`) returning `{ type: "http", host, port }` when `matchesProxyHost(new URL(details.url).hostname)`, else `{ type: "direct" }`.
  - `clear`: Chrome `chrome.proxy.settings.clear({ scope: "regular" })`; Firefox remove the listener.
- [ ] **Step 3: Implement the auth handler** `onProxyAuth(details)`: return `{ authCredentials: { username, password } }` only when `details.isProxy`, else `{}`. Register with `chrome.webRequest.onAuthRequired`: Chrome `(handler, { urls: ["<all_urls>"] }, ["asyncBlocking"])` using the async callback form; Firefox `(handler, { urls: ["<all_urls>"] }, ["blocking"])`.
- [ ] **Step 4: Wire triggers** — call `applyProxyState()` from the existing `sync()` path, on `chrome.storage.onChanged` for `proxyEnabled`/`proxyConfig`, and on worker wake.
- [ ] **Step 5: Manual verification** — load unpacked (after Task 3), set the proxy in the popup, open `https://api.ipify.org`: it shows the VPS IP; a non-Google site shows the home IP; toggling off returns Google to the home IP; a site login still prompts for its own password normally.
- [ ] **Step 6: Commit** — `git add background.js && git commit`.

### Task 6: VPS setup artifacts (independent)

**Files:**
- Create: `vps/3proxy.cfg`, `vps/setup.sh`, `vps/README.md`

- [ ] **Step 1: `vps/3proxy.cfg`** — a 3proxy config: one `users` line (placeholder `USERNAME:CL:PASSWORD`), `auth strong`, `allow USERNAME`, a single `proxy -n -a -p<PORT>` (HTTP/CONNECT, no DNS leak), bind to all interfaces. Comments mark every value the user edits.
- [ ] **Step 2: `vps/setup.sh`** — bash (`set -euo pipefail`): install 3proxy (apt or official .deb), install `3proxy.cfg` to `/etc/3proxy/3proxy.cfg`, write a systemd unit `3proxy.service`, `systemctl enable --now`, and `ufw allow <PORT>/tcp`. The script reads `PROXY_USER`, `PROXY_PASS`, `PROXY_PORT` from the environment and refuses to run if any is unset (so no secrets are baked in).
- [ ] **Step 3: `vps/README.md`** — the exact run sequence over SSH, the verification `curl -x "http://USER:PASS@VPS_IP:PORT" https://api.ipify.org` expecting the VPS IP, and the security notes from the spec (strong unique password, non-default port, treat the VPS as the trust boundary, optional fail2ban).
- [ ] **Step 4: Verify** — `bash -n vps/setup.sh`; the user runs it on the VPS and confirms the `curl` check returns the VPS IP.
- [ ] **Step 5: Commit** — `git add vps/ && git commit`.
